# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Prospera — a React career platform (ATS resume scanner, resume builder, application tracker, interview prep). Marketing landing page + an in-app dashboard, behind a real **auth backend** (`server/`, Express + MongoDB). Feature data (resumes, applications) is **persisted per-user via the API** — `DashboardLayout` loads/mutates it through `src/lib/resume/resumesApi.js` and `src/lib/applications/applicationsApi.js`. A brand-new user starts with an **empty workspace** (no seed data). **Mistral AI** (optional, server-side) powers AI ATS scoring + resume enhancement; when no key is set it falls back to a deterministic keyword heuristic.

Note: `package.json` `name` is still `parsewave` (an older name) — the product is Prospera. Don't "fix" it unless asked.

## Commands

Frontend uses standard Vite scripts (`dev`, `build`, `lint`, `preview`). There is **no test suite**, so after frontend changes verify with:

```
npm run lint && npm run build
```

This is the only self-check available and catches broken imports (e.g. a mis-pathed file move) and lint errors. The `/verify` skill runs it. Note `npm run lint` ignores `server/` (it's a separate Node package — see `eslint.config.js`).

Backend: `npm run server` (needs MongoDB running + `server/.env`, copied from `server/.env.example`). `npm run dev:all` runs Vite + the server together via `concurrently`. The frontend reaches the API through Vite's `/api` proxy → `http://localhost:4000`. Optional env: `GOOGLE_CLIENT_ID` (Google sign-in) and `MISTRAL_API_KEY` (AI features) — both disable gracefully when unset.

## Architecture

- **Auth.** `src/lib/auth/AuthContext.jsx` (`AuthProvider` / `useAuth`) is the single source of truth for the session: JWT in `localStorage` (`prospera_token`) sent as `Authorization: Bearer`, restored on load via `GET /api/auth/me`. `src/lib/api.js` is the fetch wrapper (`apiFetch`, `ApiError`). The backend (`server/src/`) is Express + Mongoose with email/password (bcrypt) + Google ID-token sign-in; routes under `/api/auth/*`. Google sign-in is gated on `GOOGLE_CLIENT_ID` (server) + `VITE_GOOGLE_CLIENT_ID` (client).
- **Routing (`react-router-dom` v7).** `<BrowserRouter>` is in `src/main.jsx`; the route tree is in `src/App.jsx`: `/` (landing), `/login`, `/signup` (wrapped in `GuestOnly` → redirect to `/app` if authed), and `/app/*` (wrapped in `RequireAuth` → redirect to `/login` if not). `/app/*` renders `DashboardLayout`, which holds the shared state and renders **descendant `<Routes>`** for each section (`dashboard`, `ats`, `studio`, `library`, `applications`, plus `ComingSoon` for interview/portfolio/profile/settings/resources). **`studio` is the unified Resume Studio** (create + edit + enhance + template, one tab — `BuildResumePage.jsx`); the old `build` and `enhance` paths now `<Navigate>`-redirect to `/app/studio` (the separate Enhance page was removed). Navigation is `navigate('/app/<tab>')` (a `go(tab)` helper passed to pages as `onNavigate`); the sidebar uses `<NavLink>`. **URLs persist on reload** (don't reintroduce `useState` view-switching). Logout does `navigate('/')` THEN `logout()` (order matters, else `RequireAuth` redirects to `/login` first).
- **State** is local React `useState` plus the auth Context. `DashboardLayout` (`src/pages/DashboardLayout.jsx`) is the single source of truth for resumes + applications: loads them once from the API on mount (loading/error/empty states), holds them in `useState`, passes them to the routed pages. Mutations go through `runMutation` (optimistic update + rollback, dismissible `actionError` banner), then reconcile from the server. The in-progress builder draft persists to `localStorage` (`prospera_build_draft`) so reloading `/app/build` keeps the work. Feature CRUD lives in `src/lib/resume/resumesApi.js` / `src/lib/applications/applicationsApi.js`; routes `/api/resumes` + `/api/applications` (both `requireAuth`, scoped to `req.user`).
- **AI (Mistral).** Server-only: `server/src/services/mistral.js` (key from `MISTRAL_API_KEY`, never sent to the client), `controllers/aiController.js` + `routes/aiRoutes.js` (`requireAuth` + rate-limited) at `/api/ai/{status,ats-scan,enhance,parse-resume}`. Frontend client `src/lib/ai.js`. ATS Scan + Enhance check `aiStatus().enabled`, use AI when on, and **fall back to the deterministic `src/lib/resume/atsKeywords.js` heuristic** on 503/error.
- **ATS matching logic.** When AI is on, the ATS report is driven by Mistral end-to-end — not just the headline score: `AtsScanPage.aiChecks()` builds the section rows + matched/missing chips from the model's `sections`/`matchedKeywords` (it judges stack equivalence, so Go/Node/Java all count as a backend language). The deterministic fallback (`atsKeywords.js`) uses **competency categories**, not a flat keyword list: `ROLE_PROFILES[].categories` (each `{ label, any:[equivalent terms] }`) + `scanRoleProfile(profile, resume)` — a category is "covered" if the resume mentions ANY of its terms, so a valid alternative stack isn't penalised (a Node/React resume vs Backend Engineer scores ~71%, not ~20%). `scanRoleProfile` is the role matcher used by ATS/Enhance/Builder/Applications; `scanResume` still handles job-posting mode (deterministic part limited to `SKILL_VOCAB`).
- **Dynamic resume sections.** Beyond the structured core (contact/summary/experience/education/skills/`projects`), a resume carries an arbitrary **`sections: [{ title, entries: [{ heading, meta, bullets[] }] }]`** so any layout (Achievements, Certifications, Awards, Languages, …) is preserved — adding a section TYPE needs no code, just data. Mistral's parse (`aiController.parseResume`) + the heuristic (`resumeParse.js`) extract them; stored on the `Resume` model (`sectionSchema`) + sanitizer + `toClientJSON`; rendered by one shared `src/components/resume/templates/CustomSections.jsx` (reuses each template's prefix classes, no new CSS) in all 6 templates; editable in the Studio's "More sections" step. `normalizeResume` + the draft converters (`resumeDraft.js`, via `withSectionIds`) carry them.
- **Categorized skills (polymorphic).** `skills` is NOT a flat list — each item is a plain string (loose skill) **or** a group `{ category, items: [String] }` (e.g. Languages: [C++, Python]), like JSON Resume / Resume Worded. `src/lib/resume/skills.js` is the single source of truth for the shape: `flattenSkills` (→ flat list for ATS matching / counts / search — used by `resumeCorpus`, readiness, section status, Library/ATS displays), `toSkillGroups`/`fromSkillGroups` (canonical groups ↔ wire; collapses to a flat string[] when no category exists, so flat resumes stay flat — no migration), `normalizeSkillsForRender` (→ `{flat, groups, grouped}`; `normalizeResume` exposes `skills` + `skillGroups`), and **`foldSkillSectionsIntoSkills(parsed)`** — the deterministic de-dup that folds any skills-like section (title matches `SKILLS_TITLE_RE`) back INTO `skills` and drops it from `sections`, so a "TECHNICAL SKILLS" block can never render twice (runs client-side on BOTH the AI and heuristic parse, in `resumeFile.js`). Rendered by the shared `src/components/resume/templates/SkillsSection.jsx` (grouped) with a flat-chip fallback in each of the 6 templates; edited as category groups in the Studio Skills step; the AI parse prompt + heuristic (`resumeParse.js` `extractSkillGroups`) emit groups. Server: `Resume.skills` is `Mixed` so `featureInput.js` `asSkills` is the sole structural guard (coerces every item to string or `{category, items[]}`); `toClientJSON` reshapes. Empty/duplicate categories are dropped on save by design (no empty headings render); skills are deduped globally.
- **Portfolio builder.** A personal-site builder at `/app/portfolio` (`src/pages/PortfolioBuilderPage.jsx`). One portfolio per user, persisted server-side (`server/src/models/Portfolio.js` unique on `user`; `portfolioController` getMine + upsert; routes `GET`/`PUT /api/portfolio`; `sanitizePortfolio` in `featureInput.js`). Client domain logic in `src/lib/portfolio/` (`portfolioApi.js`; `portfolioModel.js` = `emptyPortfolio`/`portfolioFromResume` prefill/`portfolioContent`/`portfolioDraft`/`normalizePortfolio`). `DashboardLayout` loads it in the initial `Promise.all`, holds the editing draft (`pfDraft`), **prefills from the active resume** on first visit, and **debounced-autosaves only after a real edit** (a `portfolioTouched` ref gates it, so the resume prefill never auto-creates a portfolio). Rendered by `src/components/portfolio/PortfolioDocument.jsx` (static template switch) with **3 self-contained premium templates** in `src/components/portfolio/templates/` — **Aurora** (minimal light), **Horizon** (two-column sticky rail), **Folio** (project-forward editorial). Templates are themed by one var `--pf-accent` (default orange `#f97316`, swappable), use `useReveal` scroll-reveal (only under `.pf-animate`), and **stay light in both app themes** (do NOT use app `--bg/--text` tokens). **Editor UX = gallery-first + WYSIWYG inline editing** (not a form): new users pick from a template gallery (live thumbnails), then edit the rendered portfolio DIRECTLY — click any text (contentEditable), hover a role/project/skill to reorder/remove, "+ Add" controls, and an inline `ContactEditor` for email/phone/website/socials. Mechanism: `PortfolioDocument` builds a `T(path, fallback)` text renderer + an `edit` object (`add`/`removeAt`/`moveAt`/`set`) and passes them to the template; **in view mode `T` returns a plain string and `edit` is null (markup unchanged), in edit mode `T` returns an `EditableText` (commit-on-blur) and `edit` drives the controls** — so one template serves both. Edit-mode renders the RAW draft (`ensurePortfolioShape`, not filtered) so empty items stay editable. Primitives in `src/components/portfolio/inlineEdit.jsx` (`EditableText`/`ItemControls`/`AddButton`/`ContactEditor`) + `src/lib/portfolio/path.js` (immutable `getPath`/`setPath`/`updatePath`). Plus a full-screen preview + Export (print). **Adding a template = a component (using `T`/`edit`) + CSS + an entry in `PORTFOLIO_TEMPLATES` + the `PortfolioDocument` switch.**
- **Feature backend hardening.** `server/src/utils/featureInput.js` (`sanitizeResume`/`sanitizeApplication`) whitelists + type-coerces every field — never spread `req.body` into a model (blocks setting `user`/`_id` and NoSQL operator payloads). The same sanitizer serves create (absent keys → schema defaults) and PATCH (only present keys touched). `appliedAt` back-fill (first time an app leaves `saved`) and single-active-resume exclusivity are enforced server-side.
- **ATS scores are real (only after a scan).** A resume has NO score until it's actually scanned — never a fabricated number. `Resume.scannedAt` (null until the first scan, stamped server-side by `POST /api/resumes/:id/scan` → `recordScan`/`sanitizeScan`) is the source of truth; `scanScore(resume)` in `src/lib/resume/scoreColor.js` returns the score only when scanned, else `null` (renders "Not scanned" / a dash). `AtsScanPage.runScan` records the result via `onScanned` → `handleRecordScan` (DashboardLayout) → `recordResumeScan`. Every per-resume score display gates on this: Library (cards/rows/drawer, sort/filter), Dashboard (`BoostBanner`, `ResumesGrid`, `ActionCenter`). Upload no longer fabricates a score, and the ATS picker shows honest metadata (skills/roles/PDF), not a score. (Legacy resumes with an old number but no `scannedAt` correctly read as unscanned.)
- **Original-PDF preview.** Uploaded resumes persist their original file so previews can show the user's *real* PDF, not just the extracted text re-rendered in a template. The PDF is stored base64 on the `Resume` model as `fileData` (`select: false`, so it never rides along on the list query); a `hasFile` flag + `fileType`/`fileName` are returned by `toClientJSON`, and the bytes are fetched on demand via `GET /api/resumes/:id/file`. Client: `src/components/dashboard/ResumePreview.jsx` shows `src/components/resume/PdfView.jsx` (pdf.js canvas render) when a PDF is on file, else falls back to `ResumeDocument` (template); `src/lib/resume/pdfCache.js` caches the just-uploaded bytes so the preview is instant with no refetch. ATS/Enhance uploaders call `readSourceFile` (`resumeFile.js`) → `resumeFromParsed(file, parsed, isFirst, source)` to attach the file. Built resumes have no `fileData` → template render. **ATS Scan** uses `ResumePreview`; **Enhance** keeps `ResumeDocument` (its preview must reflect live edits).
- **LaTeX PDF export (Resume Studio Download).** The HTML/CSS templates power the on-screen editor + live preview; **the Download button compiles a print-perfect PDF via LaTeX** (Overleaf-grade, consistent, real `\href` links). `server/src/services/latexResume.js` (`buildResumeTex`) turns the sanitized résumé content into a `.tex` (single-pass `tex()` escaper for all LaTeX specials; grouped/flat skills; custom sections; accent color); `resumeController.render` writes it to a temp dir and runs **Tectonic** (`POST /api/resumes/render`, requireAuth; `TECTONIC_PATH` env or `tectonic` on PATH; no shell-escape; temp dir cleaned up) and streams back `application/pdf`. Client: `apiBlob` (`lib/api.js`) → `renderResumePdf` (`resumesApi.js`) → `BuildResumePage.handleDownload` triggers the browser download, **falling back to `window.print()` if the engine is unavailable** (so Download always works). The host must have Tectonic installed for LaTeX output (see `server/.env.example`); the LaTeX PDF intentionally doesn't 1:1-match the HTML preview (different layout engine) — it's a curated clean template.

## Folder structure (follow this when adding files)

- `src/pages/` — full screens / routed views (`LandingPage`, `LoginPage`, `SignupPage`, `DashboardLayout` (the `/app` shell), `DashboardHome`, `LibraryPage`, `AtsScanPage`, `BuildResumePage` (the **Resume Studio** at `/app/studio` — Build + Enhance merged; still imports `css/EnhanceResumePage.css` for the shared `.en-*` classes), `ApplicationsPage`, `PortfolioBuilderPage` (the portfolio builder at `/app/portfolio`), `ComingSoon`).
- `src/components/portfolio/` — the portfolio builder's render layer: `PortfolioDocument` + `templates/` (Aurora/Horizon/Folio + `useReveal` + `css/`). Self-contained premium personal-site templates, themed by `--pf-accent`, always light.
- `src/components/dashboard/`, `src/components/landing/`, `src/components/resume/` — feature components grouped by area. `src/components/resume/templates/` holds the resume templates + `ResumePaper`.
- `src/lib/` — non-UI logic, grouped by domain: `lib/api.js` (generic fetch wrapper), `lib/ai.js` (Mistral client), `lib/auth/` (AuthContext), `lib/resume/` (draft, templates, sample, parse, file, upload, atsKeywords, scoreColor, resumesApi, skills), `lib/applications/` (applications domain logic + applicationsApi), `lib/portfolio/` (portfolioApi + portfolioModel), `lib/theme/` (ThemeContext). When adding resume/applications/portfolio logic, put it in the matching domain folder.
- CSS is co-located in a `css/` subfolder next to its components (e.g. `src/components/dashboard/css/Sidebar.css`); global tokens/typography live in `src/index.css`. Inline `style={}` mixed with CSS files is accepted here.
- **Theming (light/dark).** Colors are CSS custom properties (tokens) defined in `src/index.css`: light values in `:root`, dark overrides in `:root[data-theme="dark"]`. The theme is just a `data-theme` attribute on `<html>` — set pre-paint by an inline script in `index.html` (saved choice in `localStorage` `prospera_theme`, else OS `prefers-color-scheme`; no flash) and then owned by `src/lib/theme/ThemeContext.jsx` (`ThemeProvider`/`useTheme`, wrapped in `main.jsx`). `src/components/ThemeToggle.jsx` (Sun/Moon) lives in the Sidebar + LandingHeader. **Use tokens, not raw hex**, so new UI themes automatically — `--bg-main/-card/-elevated/-inset`, `--text-main/-muted/-light/-inverse`, `--border-color/-dark/-strong`, `--primary-accent(-hover)`, `--primary-light`, state `--success/-warning/-info/-danger/-purple` (+ `-bg`, `-strong`, `--danger-text/-border`), `--overlay`, `--chip-bg`, `--hover-bg`, `--glass-bg`. `--text-inverse` is white-on-accent (stays white in dark). The **resume document stays light in both themes** — templates + `ResumePaper.css` hardcode `#fff`/`#111827` and must NOT use these tokens (a resume is a white-paper document / PDF).

A new full screen goes in `src/pages/` and gets a route in `src/App.jsx` (or `DashboardLayout` for an `/app` section).

## Assets (using the wrong location breaks the image)

- `src/assets/*` — imported in JS (`import hero from '../../assets/hero.png'`). Vite hashes and bundles these.
- `public/assets/*` — referenced by absolute path (`src="/assets/alex_avatar.png"`). Served as-is.
